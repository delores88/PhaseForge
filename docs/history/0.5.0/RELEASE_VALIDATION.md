# PhaseForge 0.5.0 — validation record

This complete source release increments the supplied 0.4.0 full project. Every
original project path remains; no npm/Cargo dependency declarations or frontend
framework were upgraded. The former release's validation is retained separately
under `docs/history/0.4.0/` and must not be confused with this release's checks.

The independent worker tests run real numerical methods and an actual isolated
Python subprocess. They test failure as well as agreement. The SciPy comparison
was available and executed here; when SciPy is absent, that one optional test is
skipped and the standard-library verifier still operates. No scientific result
about the user's experiment was generated by these synthetic test fixtures.

Browser fixture screenshots were inspected. These are static layouts with
synthetic state, not a running application. They do not test React hydration,
interactive form submission, GPU/WebGL, or Rust HTTP handlers. Original core
files and tests are retained; retaining files alone does not establish absence
of native regressions.

## Included native tests, NOT executed here

26 new native Rust unit tests cover novelty-directed selection and dossier,
comparison, provenance, review, restart and cascade contracts. The new
`tests/verification_runtime_smoke.py` launches a genuinely built isolated backend,
runs a real novelty-directed study plus control, freezes and approves a
verification job, checks two independent numerical implementations and four
perturbations, persists an inconclusive review and verifies the actual generated
research bundle. It confirms that this workflow incurs no model usage.

The test is wired into Windows/Linux CI after the existing laboratory and
discovery integration tests. **Neither CI nor these native tests ran here.**
Rust/Cargo, Windows PowerShell/MSVC and resolved npm dependencies were absent;
registry access failed. Therefore no native compilation, native service execution,
full Next.js production build, Windows installation, live provider/Crossref call,
physical GPU test, native verifier launch or backend research-export generation
is represented as passed in this packaging environment.

The complete Windows TXT installer runs the real Cargo build/tests and Next.js
production build on the development machine. Keep the known-working 0.4.0
installation and a backup of application data until those checks pass. The
optional `INSTALL_VERIFIER.txt` separately installs/detects Python, creates a
standard-library-only environment and executes the verifier regression suite.

## Scientific scope of acceptance

Two implementations agreeing tests implementation, not truth of a physical
model. New post-selection perturbations characterize a declared neighborhood,
not global stability, independent population sampling, corrected statistical
significance, or novelty. Scaled reference distances are neither symmetry
classification nor comprehensive literature comparison. Search metadata is not
full-text evidence. A human review is evidence-bound attribution, not a trusted
identity signature. The maximum automated assessment is ready for external
review, never a novelty certificate.

## Final archive acceptance

The archive is released only after regenerating all payload checksums, testing
ZIP CRC, extracting into a fresh directory, byte-comparing every file, verifying
all internal hashes, confirming every baseline path is retained and rerunning
the executable non-native suites from the extraction. Exact file counts, archive
hashes and the performed acceptance results are recorded beside the ZIP in the
external package report. Local caches, logs, databases, credentials, virtual
environments and dependency/build directories are excluded.
