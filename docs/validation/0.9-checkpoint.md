## First packaging attempt: retained validation failure

With `--config.compression=store`, electron-builder 26.15.3 produced an installer
of **593,820,015 bytes**, then rejected it because it was smaller than the
**661,189,894-byte** generated external archive. The failed installer is retained
under `.local/validation/fifth-package-store-failure/`, SHA-256
`9b323aa64b1712cfd603f2bac8dfd0860d2b156cc0742bd549b3f0b8da1221a0`.
The [receipt](../../.local/validation/fifth-package-store-failure/report.json)
records the failure, dirty source and 114.68 GiB free disk space. This candidate
was not installed. The old external archive's size was recorded, but its bytes
were not preserved before the retry; no archived-copy claim is made.

Read-only inspection established a comparison mismatch:

- `desktop/build/installer.nsh:16` defines `APP_BUILD_DIR` inside NSIS processing.
  The bundled `templates/nsis/include/installer.nsh:9–11` consequently embeds
  unpacked application files with `File /r`, bypassing external-archive extraction.
- `NsisTarget` still generates the external archive and retains `APP_64` in its
  JavaScript defines. The custom include does not update that JavaScript object.
- `nsisValidation.ts:30–54` (retained in the installed package's source map) sums
  `APP_64`/`APP_32`/`APP_ARM64` archive sizes and compares that sum with the installer.
  It does not account for this direct-file payload path. Therefore this particular
  size failure alone does not prove truncation, nor does the review establish
  that the failed installer contains every required byte.

The retry uses standard supported compression, leaving all validation enabled.
`platformPackager.js:53–59` defaults to `normal`; `NsisTarget.js:260–270` then uses
NSIS zlib, while `targets/archive.js` applies the normal 7z compression path.
The current Windows candidate CI uses the same package command without a store
override. Its later `upload-artifact` `compression-level: 0` affects artifact
upload, not installer compression.

An existing external archive can be reused solely by modification time, even
when compression settings change. The coordinator confirmed that this retry
actually launched a fresh 7za process and wrote a new archive, with no
`skipped archiving` output. Normal compression is a valid retry, not a proof that
two different payload encodings must satisfy the comparison or that the installed
payload is complete. The final file inventory and native checks remain necessary.
