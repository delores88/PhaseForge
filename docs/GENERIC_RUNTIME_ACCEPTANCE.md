# Generic-runtime acceptance contract

A release qualifies as the generic-runtime refactor only when all of the following are true.

## No canned scientific cases

- Core source contains no named-problem implementation.
- Core dispatch contains no scenario identifier switch.
- No known answer is injected into a search population.
- No executable scientific example is bundled as the default experience.
- Deleting local research data returns the product to an empty but usable laboratory.

## Research-object authoring

- Chat can create a complete manifest from a question through a configured provider.
- Chat can revise an existing manifest through immutable child revisions.
- A proposal may return an explicit capability gap.
- Unsupported requests are not silently mapped to an available model.
- Manual manifest import passes through the same validator.

## Trusted execution boundary

- The backend executes only recognized generic model variants.
- Expressions are parsed and bounded before execution.
- Model output cannot invoke shell, native compilation, arbitrary files, network calls or raw shaders.
- Resource limits, cancellation and provenance apply to every run.

## Workspace contract

- Research chat is visible beside the laboratory.
- Chat collapses completely and restores state.
- Desktop chat width is pointer-resizable.
- Width is clamped to a 10% minimum and 60% maximum.
- The laboratory expands and contracts with the drawer.
- Narrow screens use an overlay rather than crushing the scientific view.

## Evidence contract

- Every run references one immutable manifest ID and revision.
- The numerical backend used is recorded.
- GPU fallback is disclosed.
- Falsification output is distinguishable from primary metrics.
- No placeholder result is rendered as completed science.
