# PhaseForge 0.6.0 — complete incremental research-workbench release

Baseline: supplied PhaseForge 0.5.0 complete source. No dependency/framework replacement.

## Added

- Persistent source-linked research programmes; ordered tasks, prerequisites, explicit
  acceptance criteria, missing inputs, task-to-chat preparation and append-only human progress.
- Intent selection: plan, discovery, benchmark and auto. Broad goals get actionable
  programmes rather than a required dead-end capability response. No silent safety bypass.
- Explicit Europe PMC query consent, bounded metadata/abstract retrieval, response hashes,
  source-ID validation and failed-search records. No full-paper review is invented.
- Local bounded CSV descriptive profiles and exact UTF-8 input hashes. Raw rows not retained.
- ODE CPU limit128, separate per-step trajectory reducers, named metrics usable in screening,
  constraints, objectives, findings, Discovery selection and independent verification.
- New immutable `resolution_ladder` type for real h/2+h/4 trials. Legacy StepHalving unchanged.
- Per-entity rendered radii in coordinate units, no offset-marker size imitation.
- Actual GPU compatibility preflight, RAM-aware batching/admission and recorded effective limits.
- Source-version-compatible independent replay for existing v0.5.0 verification protocols.

## Preserved / corrected

All baseline paths remain. Database/keyring paths, usage limits, stopping, provider-model
selection, installation structure, themes, resizable chat and previous science tools remain.
Failed challenge execution is retained as incomplete evidence rather than deleting a good
baseline; constraint failures also influence the challenge verdict. New first-passage
measurements mark censored outcomes explicitly. Unknown frozen worker hashes are not replaced.

## Boundaries

No new executing MD/QM adapter, biological validation, clinical efficacy inference, material
collision response, exact continuous event localization or discovery guarantee is claimed.
Sampled extrema/crossings need resolution studies. GPU detection is not solver eligibility.
CPU batching and memory estimates do not impose a hard OS RAM quota. Research/data summaries
are evidence inputs, not automatically trusted truth. Paid/public actions remain explicit.

Read `docs/RELEASE_VALIDATION.md` for executed checks versus native/Windows/live-service tests
that remain unexecuted in this packaging environment.
