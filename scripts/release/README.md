# Stable Windows candidate evidence

The manually dispatched `marketplace-candidates.yml` workflow builds Windows x64 NSIS only. It never creates or publishes a GitHub release, signs with a purchased OS certificate, or submits to DeloresAI. Root must freeze the final version and clean source commit before dispatch. Candidate collection rejects prerelease version suffixes and records stable intent; it does not claim marketplace admission.

The older Linux/macOS archive helpers and their regression fixtures remain available for historical evidence interpretation. They do not establish support for the current generated-code boundary, which requires Windows. A later platform release requires its own implementation and native evidence. Never append artifacts to a submitted immutable release or reuse an older runtime profile for changed bytes.

Windows uses the pinned NSIS 3.12 toolset and a small `desktop/build/installer.nsh` include. The include selects the standard installer's built-in `File /r` branch, so the installer compresses and embeds the native app directly. This removes the obsolete Nsis7z and NSISunz extraction plugins; merely selecting the newer compiler bundle would still ship those old decoders. The standard installer wizard, architecture checks, process-close handling, shortcuts and uninstaller remain in use. The current candidate targets x64; ARM64 is not covered by these amd64 runtime seeds or their acceptance. Web installers, ia32 and combined architectures are refused. The hosted acceptance checks the final installed files and lifecycle; the full installer wrapper is a separate scan scope because temporary installer plugins are absent from the installed app inventory.

Each job builds from the exact clean dispatched commit and locked dependencies. Pinned cargo-auditable embeds actual compiler dependency metadata in the backend. The staged runtime includes that metadata bound to its binary hash, the complete Cargo lock with its scope disclosed, frontend/desktop input locks, and hashes of the static UI actually packaged. The build-only release tool dependencies are never packaged.

`build_seeds.py` builds portable `science-v3` and `python-numpy-v2` runtime seeds from SHA256-pinned official CPython 3.13.15 binary/source archives and exact NumPy 2.4.6, OpenMM 8.5.2 and Pillow 12.3.0 wheels. It executes no downloaded code and uses no pip installation. Every original embedded native file and wheel member remains inspectable outside ASAR. Science-v3 adds a byte-identical `MSVCP140.dll` alias from the pinned NumPy wheel so OpenMM's ordinary DLL import resolves inside the managed runtime. Actual runtime acceptance verifies the loaded path. Microsoft notices and terms accompany the component separately from MIT/BSD notices and are pinned by staging and payload checks. The generated runtime is unchanged; existing science-v2 artifacts remain readable, while resuming a solver with a different recorded runtime requires a new immutable attempt.

The exact embedded standard-library module set is mapped to matching pinned `Lib/*.py` source; resource files are retained and the bytecode/configuration replacements are recorded. The frozen manifests in `tools/runtime-seeds/` have no timestamps or host paths. `--freeze` only creates new manifests; CI reconstructs and compares them byte-for-byte without changing source. The hosted Python is an explicit build/evidence tool, not a runtime prerequisite of the portable seeds. Native identity evidence maps all 127 shipped runtime native files to exact upstream members, records observed PE versions and imports, and explicitly identifies missing metadata. Optional OpenCL host support is distinct from CPU/Reference operation.

The installer contains these files under `resources/runtime/runtime-seeds/`. The backend copies and verifies them in app data before computation. `materials.mjs` verifies staged files against frozen manifests; `managed_runtime.py` independently compares installed seeds, managed copies, exact outer/inner manifests and all native/file pins. It reports declared archive pins separately from independently replayed archive bytes and does not assert a complete SBOM. Payload Syft must discover NumPy/OpenMM/Pillow metadata; supplemental runtime components retain their exact evidence scope. There are no post-install executable downloads for these bundled workflows. Historical venv inventory explicitly records its external host-Python dependency and missing wheel archive provenance; it cannot satisfy bundled release acceptance.

The Windows installer presents the pinned Microsoft-runtime agreement on interactive installs and updates. Unattended deployment requires explicit `/ACCEPT_MSVC_TERMS=MSVC-2026-09-11` alongside `/S`; missing or different assent is refused. The hosted installing developer supplies that argument and retains the terms hash. This does not claim that the hosted silent check exercised the interactive checkbox. PhaseForge itself remains MIT licensed.

`frontend-modules.json` links each emitted JavaScript bundle to its actual shipped source map and mapped source-content hashes. The installed payload is parsed again and must exactly reproduce the staged evidence. Mapping gaps remain explicit; dependency versions are not guessed from a lockfile. Source maps are included in the final package, and module summary/gaps are retained in the build manifest and raw checks archive.

`native.mjs` runs only in an explicitly enabled GitHub-hosted disposable job. Windows installs the exact NSIS package into a new isolated directory. Chromium's sandbox remains enabled. Playwright opens a local debugger transport for observation; this is not an uninstrumented launch certification. The app creates its own backend and authenticated readiness channel. The original dx/dt = 1 fixture remains, including refinement, Results UI and retained trajectories. `native-laboratory.mjs` additionally creates real OpenMM, Fourier diffusion and LPAC NumPy jobs through the normal laboratory API without model credentials, checks their retained numerical evidence, exercises cancellation and an interrupted generated attempt, and verifies explicit restart and restored data. It retains actual job/process/boundary receipts and rechecks zero provider tokens. Normal Quit must stop recorded child processes and ports; generated restart is a new immutable attempt from retained source, not a claim of solver checkpoint recovery. Cleanup targets only recorded PID plus creation-time identities.

During those launches, inert IPv4 and IPv6 loopback listeners occupy legacy ports 3000 and 7331. They must observe zero connections, including TCP-only readiness probes. The actual backend endpoint comes from `/api/health.endpoint` after the desktop verifies its own child; its dynamically assigned port must differ from those fixtures and the UI port 7332, then close after normal Quit. Launcher and Electron process trees are both sampled with creation-time identities so exited/reused PIDs cannot become cleanup targets. Copied AppImage links retain their relative targets, and payload inventory still rejects escaping links.

Acceptance records the actual hosted OS, architecture, RAM, installed bytes and sampled process memory. These observations do not establish minimum supported RAM/OS claims. Hosted Windows Server 2025 is not Windows 11 acceptance. The exact final Windows 11 app needs separate native checks before claiming that environment. Paid AI providers and optional Blender/CAD engines remain outside this offline fixture. Passing helper fixtures or building runtime seeds is not passing installed acceptance.

Source Syft includes development dependencies because Electron is a declared devDependency that becomes shipped runtime code. Payload Syft excludes clearly identified build-input locks and optional-engine requirements from its package claims; those files remain covered by full payload hashes. ASAR is separately expanded with bounded trusted code. Actual `process.versions` and backend SQLite observations supplement scanner coverage. Raw source, payload, ASAR and runtime Grype results and redacted Gitleaks reports remain in the checks ZIP. There are no blanket CVE/secret exceptions. Completing these tools does **not** mean security acceptance: unresolved High/Critical findings, secret findings, ClamAV inspection and signed marketplace admission still require review. A tool error prevents candidate assembly.

A separate `runtime-screening-aliases.cdx.json` widens candidate matching to Google Chrome advisories for vendored Chromium and the numeric upstream V8 version. Google Chrome is not claimed as an installed component. V8's `google:v8` vendor/product mapping is documented in [NVD's CVE record](https://nvd.nist.gov/vuln/detail/cve-2024-3914). These conservative screening aliases and every resulting raw match remain distinct from the payload inventory; OS applicability and Electron backports are never waived automatically.

Electron may report `process.versions.openssl` as the compatibility placeholder `0.0.0`. This does not become an OpenSSL component or CPE. The raw value is retained, while `runtime-identity-gaps.json`, the scanner review and build manifest explicitly leave the crypto identity unresolved until the exact BoringSSL source/archive and packaged-native-byte mapping is verified. Inventory completeness is never inferred from zero vulnerability matches.

Candidate assets include the original installer once, source and payload CycloneDX inventories, raw checks/native receipts ZIP, build manifest, checksums, detached GitHub OIDC SLSA bundle, freshly obtained GitHub trusted root and exact-commit verification. The pinned GitHub CLI authenticates its root bootstrap; consumers should obtain fresh roots and enforce their own expected source/workflow policy. OIDC proves build origin, not scientific validity or a vulnerability-free application. The build manifest is **not** `deloresai.manifest.json`.

Tool versions and official archive SHA-256 values are pinned in `tool-pins.json`. `@actions/attest` uses GitHub's private Sigstore trust domain with `skipWrite: true`; no repository attestation API write or public-good transparency disclosure occurs. The build-only `@sigstore/core` override fixes the UTF-8 DSSE payload-type length vulnerability and has a direct regression test.

Local non-destructive verification:

```text
npm ci --prefix scripts/release --ignore-scripts --no-audit --no-fund
node --test scripts/release/*.test.mjs
python -m unittest discover -s scripts/release -p "test_*.py"
```

Native acceptance intentionally refuses normal local execution. Do not fake GitHub-hosted environment variables to bypass that guard. Failed native jobs upload diagnostic JSON/screenshots only; incomplete packages are never labeled validated or admitted.
